# 绘梦儿童绘本商城

本工程按《绘梦儿童绘本商城完整实施说明》组织，包含管理员网页端、Node.js API、SQLite 数据库和 Android 原生 Java/XML 用户与商家端。

## 当前版本 1.2.0（2026-11-13）

新增买家、商家和管理员 AI 助手，按登录身份隔离会话与同步队列，更新商家工作台、商品维护和订单状态展示，并纳入 SQLite 规范化维护工具。此版本作为三端界面改版前的基线。安装与验收范围见 [版本说明](docs/releases/android-1.2.0.md)。

## 1.1.1 原数据恢复与本地使用

安装后无需先启动电脑服务或登录网络账号，即可进入本地空间。地址、资料、收藏、购物车、帖子、评论、商品草稿及订单意向先写入应用私有 SQLite；图片保存到应用私有目录。尚未同步过的网络内容需联网获取，此修复包预置本项目原库的 20 件公开商品、8 篇公开帖子及公共通知和现存图片。当前模拟器原账号的个人消息、地址、收藏、订单已单独迁入其私有 SQLite；个人数据不随 APK 分发。

“我的 → 外观与壁纸 → 本地数据与网络账号”可进入“本地与网络同步”，查看待上传和冲突；点“关联或切换网络账号”后，完成原账号验证并确认关联。应用前台会自动检查服务，按图片、操作、网络快照的顺序同步；关闭服务、退出网络登录均保留本地空间。不同网络账号与服务地址使用独立空间。订单、付款、送审、发货等只有收到服务器确认才改变网络业务状态，离线时显示待确认意向。

此 APK 为 Debug 模拟器包，服务地址仍为 `http://10.0.2.2:3000/api/v1/`。注册、密码变更及首次验证网络账号需要服务在线。验证结果与限制见 [本地优先验证](docs/verification/2026-10-14-local-data-recovery.md)，没有自动上传 GitHub。

## 目录

- `html/`：管理网页，`html/launcher/` 存放 Windows 控制中心及其服务脚本。
- `server/`：三端共用的 Express API、SQLite 迁移、演示素材和服务端测试。
- `android-app/`：Android Java/XML 工程，用户与商家共用一个 APK，通过角色进入独立导航。
- `docs/`：需求、接口、环境与数据维护说明。历史发行说明和验收记录分别放在 `docs/releases/` 和 `docs/verification/`。
- `scripts/`：跨端联调、控制中心回归、性能测量和离线内容导出。
- `shared/assets/`：共用的原始品牌素材。
- `output/`：本地 APK、论文材料、测试截图等交付和验证产物。测试需要临时数据库时也放在这里，并使用单独的目录。

活动数据库位于 `server/data/huimeng.db`，用户图片位于 `server/uploads/`，备份默认位于 `server/data/backups/`。`html/server/data/` 存放控制中心状态、日志及历史数据库。Android 使用自己的私有 SQLite 数据库，通过操作队列与服务器同步。

数据库结构与维护说明见 [完整数据字典](docs/database-dictionary.md)，覆盖当前服务端 40 张表和 Android 7 张本地技术表；[3NF 调整设计](docs/superpowers/specs/2026-10-24-database-normalization-design.md)说明后续拟调整范围、交易快照保留和兼容要求，当前尚未执行结构迁移。聊天、部分售后及反馈的查询方式见 [专项数据库说明](docs/customer-services-database.md)。

`node_modules/` 是构建和运行依赖。`.npm-cache/`、`.gradle-user-home/` 和 `android-app/.gradle/` 是本地缓存。`html/dist/`、`server/dist/` 和 Android 各级 `build/` 由构建生成。`android-app/.idea/` 保存本地 Android Studio 工程设置。

生成新的离线内容时，先备份业务库，再用 `node scripts/export-android-offline.mjs --database <备份数据库绝对路径> --user <原账号ID> --output output/<迁移目录>` 导出；随后构建 Android。`assets/bootstrap` 为忽略提交的本地公开内容；账号迁移文件和备份仅保存在 output，不进入源码或 APK。

## Windows 一键启动（网站与 App 共用服务）

1. 安装 Node.js 24，并解压完整的 `huimeng` 文件夹。
2. **双击 `huimeng\html\网站启动.vbs`**，在控制中心点击“打开服务”。首次运行需要联网安装 npm 依赖，随后自动初始化共享数据库并启动网站和 Android API；运行日志可直接通过控制中心主界面的“运行日志”按钮打开，也保留设置菜单入口。
3. 控制中心确认“服务正在运行”后，网页自动打开 `http://127.0.0.1:3000/login`。电脑浏览器访问 `http://127.0.0.1:3000/api/v1/health` 应显示 `service: huimeng-api`。
4. 在 Android Studio 中运行模拟器 App；它使用 `http://10.0.2.2:3000/api/v1/`，**不需要再启动其他服务文件**。关闭服务也在同一个控制中心操作。

根目录 `start-dev.bat` 为旧入口的兼容转发，功能与 `html/网站启动.vbs` 相同（BAT 兼容入口可能短暂显示命令窗口）；不要两次启动。弃用的独立后台和旧 PowerShell 启动脚本已移除。服务器唯一业务数据库为 `server/data/huimeng.db`；原 `html/server/data/huimeng.db` 保留为历史数据，不参与同步。不要删除数据库或 `server/uploads` 中的用户图片。

控制中心每次启动校验构建输入与产物，未变化时复用已验证构建；变化时重新构建网页和 API，再执行幂等迁移与演示数据检查，不会清空现有业务数据。运行日志按记录时间倒序显示，最新内容在顶部，保留最近三天（72 小时）；启动记录按次单独保存，运行记录按小时保存，每小时清理过期记录。DEBUG 筛选同时保留错误，便于排查。`html/server/data` 现在只承担控制中心状态、日志及历史数据保留。

手机和网页使用同一 API 和数据库。手机新增用户、商品、帖子、评论或更新订单后，管理网页通过 SSE 推送刷新；断线重连、恢复标签页后会重新读取数据，断线期间每 15 秒尝试刷新。Android 主导航各页在登录后首次初始化一次，切换时保留页面和滚动位置；首页、社区、消息、我的及商家工作台/商品页通过手动下拉刷新。订单与物流页面在前台每约 5 秒静默同步，离开页面停止轮询，数据未变化时跳过列表或商品区域重绘。审核中的商品会出现在后台审核页，通过审核后才出现在用户商城。

社区列表与阅读笔记详情支持点击作者头像或名称进入读者主页。主页仅显示公开昵称、头像、公开笔记及这些笔记的获赞数，不公开账户、联系方式或隐藏帖子。新增主页接口为 `GET /api/v1/community/users/:id`，需要登录。更新服务源码后，需要在现有控制中心关闭并重新打开服务以加载最新 API。

首页已接入五张确认后的写实海报，支持左右首尾循环滑动，每 5 秒自动切换；手动操作后重新计时，离开首页或应用进入后台时暂停。海报按 37:17 比例完整显示，保留原宣传区域圆角。最新 Android 包为 [1.1.5 APK](https://github.com/zhangsanfeng25/huimeng/releases/download/android-v1.1.5/huimeng-1.1.5.apk)，保留历史包。新增本地 SQLite、离线操作与联网同步，并恢复运行日志和优化服务启动。功能与验证记录见 `android-app/BUILD_NOTES.md`。

首页年龄、主题分类和“查看全部”进入独立结果页，可继续搜索、排序和分页。评论时间按设备本地日期显示：今天为小时分钟、本年非今天为月日、往年为年月日。下单、支付、发货和确认收货后，买家与对应商家会收到未读订单提醒；网页管理端代处理发货或完成订单时同样同步。消息页进入时读取最新列表，前台订阅 SSE，断线时每约 5 秒重试同步，离开后停止。

默认头像已提供五种阅读与成长图片，入口为 App 的“我的 → 外观与壁纸设置 → 更换头像”或“编辑账户”。点选立即保存至共用 API；用户管理列表及用户/商家详情显示相同头像，并通过 SSE 自动更新。图库上传与裁剪继续保留，头像统一圆形裁切及细边框。现有六个用户/商家账户已均匀分配五张头像，替换前已保存数据库快照；新注册及后台新建用户优先采用使用次数最少的默认头像。

检查命令：在项目根目录运行 `npm run build`、`npm run lint`、`npm test`。同步回归测试使用临时数据库，不会向业务数据库添加测试用户和商品。依赖统一由根目录 `package-lock.json` 管理。

本机业务库已于 2026-10-24 完成规范化迁移，当前 47 表；[数据字典](docs/database-dictionary.md)逐表记录用途、字段、候选键及函数依赖，[验收记录](docs/verification/2026-10-24-database-normalization.md)记录三端检查、旧 APK 兼容、备份恢复与覆盖限制。保留旧库和完整备份；日常启动不会自动执行规范化切换。

源码上传范围、日常提交与发布标签规则见 [源码上传与版本管理](docs/version-management.md)。业务数据库、备份及用户上传图片只保留在本机或独立备份中，不通过 Git 同步。

正式发行版见 [Android 1.2.0 Release](https://github.com/zhangsanfeng25/huimeng/releases/tag/android-v1.2.0)。下载附件 `huimeng-1.2.0.apk`，使用方式与验证范围见版本说明。当前 APK 为 Debug 模拟器演示包，私有仓库需登录有访问权限的 GitHub 账号。

## Android 构建

在 Android Studio 中只打开 `android-app` 文件夹，等待 SDK 与依赖同步，然后运行 `gradlew.bat assembleDebug`。当前构建的 Debug APK 位于 `android-app/app/build/intermediates/apk/debug/app-debug.apk`；不同 Gradle 插件版本也可能输出到 `app/build/outputs/apk/debug`。Release 版本不允许明文 HTTP；本地 HTTP 仅在 Debug Manifest 中开启。详细步骤见 `docs/android_studio_guide.md`。

支付、物流和短信均为本地模拟；所有核心数据写入 `server/data/huimeng.db`。

## 控制中心数据管理与后台图文

控制中心现有四个独立按钮：**备份数据库、恢复数据库、导出业务数据、查询管理记录**。备份使用 SQLite 在线 backup API，同时复制上传图片并生成 SHA-256 清单，默认保存至 `server/data/backups`。恢复需先关闭服务，选择完整备份目录并确认；验证通过后自动保存恢复前快照，替换数据库和上传图片，并清除旧登录会话。保留完整备份目录，勿删除其中的 `uploads` 或 `manifest.json`。

导出生成 20 类业务 CSV 和 JSON（含聊天、售后和反馈），剔除密码散列、令牌等字段，CSV 转义公式前缀。查询支持本地日期和关键词，最多展示最新 1000 条匹配记录，同时包含网站审计与本地维护操作。运行日志保留三天，业务审计和备份不会按此规则自动删除。

商品审核页“查看”读取所选修订版本，展示图文、适龄、价格、库存、商家和审核信息；只能审核最新待审版本，驳回原因必填。商品列表“查看 → 维护商品图文”可补充真实图片、设置封面并保存介绍，使用共享数据库供网页与 App 读取。社区与商品图片支持统一预览、模拟器地址归一化和缺图提示。演示数据中有些图片路径没有对应原图，需上传真实素材补全，不能自动恢复不存在的文件。

后台统一连接状态与最后成功读取时间，网络恢复时重新连接并刷新。商品、审核、订单等列表支持状态和商家筛选及分页；工作台动态完整换行、按时间排序，成交金额统计已支付且未取消订单，并扣除已登记退款金额。

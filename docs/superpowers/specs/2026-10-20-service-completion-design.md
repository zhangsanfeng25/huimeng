# 三端服务闭环设计（用户已确认实施）

依据聊天中已批准方案，补齐分类、售后、文字聊天、反馈，新增用户要求：启动控制服务，在模拟器购买并核对管理员实时显示。

## 边界
- 保留现有未提交变更、业务库、上传文件、历史 APK；不上传 GitHub。
- Java/XML + React + Express + SQLite；现有视觉体系，不整体重设计。
- 售后按店铺订单整单全额：商家初审、管理员复核；仅退款限未发货，退货退款限已发货/完成；退款为演示记账。
- 售后状态与原订单分离；禁止并发重复退款、重复补库存、售后中发货/确认收货。
- 私聊：买家和店铺固定会话，文字和商品/订单上下文，已读/未读、分页、失败重试；服务端权限校验，不把正文广播给其他账号。
- 反馈：买家和商家提交、管理员回复、处理中/已解决、用户补充。
- 新增网络敏感操作由服务端确认；离线仅缓存记录和草稿，不伪造已送达/审核成功。
- 分类复用现有页，修正运行版本、同步及启停用逻辑。

## 数据
新增 after_sales、after_sale_events、refunds、conversations、chat_messages、conversation_reads、feedbacks、feedback_replies；金额使用整数分，外键、唯一约束和索引。
电脑库 server/data/huimeng.db 为共享业务源；手机 huimeng-local.db 为隔离的本地投影。新接口显式走认证网络，按账号缓存。

## 验收
临时库验证状态机、越权、幂等、订单冻结；模拟器购买 -> 同步回执 -> API 数据库 -> 管理员页面自动刷新；双向聊天、售后退款、反馈闭环；数据库完整性、APK 版本/签名/哈希。

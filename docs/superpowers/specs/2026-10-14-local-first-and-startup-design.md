# 软件以及网站优化 1：本地优先、同步与启动体验设计

日期：2026-10-14

状态：用户已确认总体方向；本文待用户审核。本文是设计，不代表功能已实现或测试通过。

## 1. 需求与验收目标

用户要求：恢复控制中心运行日志入口；加快网站等服务启动；Android 无论服务是否启动都能进入并操作，未连接服务时在手机内部完成操作，恢复连接后上传到服务端。

已确认方向：首次安装无服务也能创建本地身份进入；买家和商家均有本地工作空间；本地保存业务数据和图片；联网验证网络账号后同步；冲突不能直接覆盖；离线订单和支付意向不冒充服务端已确认状态。

保持 Java/XML、Volley、React/Vite、Express/SQLite 技术栈和现有视觉体系。网站仍为服务端管理后台，本次不增加网站离线管理、远程托管或新支付渠道。

完成标准是可安装 APK、可运行的服务与网站、日志入口和可复查的测试结果；不以跳过登录后只能看到报错页面作为完成。

## 2. 当前代码证据与限制

- `html/launcher/launcher.ps1` 已有 `Open-RunLog` 和筛选窗口，但入口位于设置菜单；截图中没有直接可见的日志按钮。
- `html/launcher/prepare.mjs` 已按输入和产物指纹复用构建；不能把每次都全量构建当作已确认原因。worker 仍串行执行后端检查/构建、迁移与初始化、网站检查/构建、运行进程启动。
- `WelcomeActivity` 默认等待三秒，记住登录后仍先请求 `auth/me`，失败回登录页。`MainActivity` 无 token 时回登录页；`ApiClient` 无离线实现且关闭请求缓存，401 会清除会话并跳转。
- `LocalCartStore` 有按账号存储，但刷新仍依赖服务端，不能承担完整本地业务。`AccountSync` 仅处理前台事件与轮询，不是持久化上传队列。
- 服务端 `/checkout` 与付款已有幂等处理，其他新增内容和图片上传尚无统一同步去重协议；订单已有版本，不能据此推定所有实体都有并发保护。
- 上一轮实测 127.0.0.1:3000 健康接口连接被拒绝；ADB 受到用户目录权限限制，模拟器内网络尚未验证。日志专项回归上轮通过，不代表完整测试或本轮代码通过。
- 当前源码 Android 版本为 1.0.36 / 26；这是本地配置证据，不是对远程发行状态的核验。

## 3. 方案选择

| 方案 | 效果与代价 | 决策 |
| --- | --- | --- |
| 跳过登录，加 GET 缓存 | 改动少，但首次无网无内容，写操作失败，不能覆盖用户要求 | 不采用 |
| Android 本地业务库 + 持久化操作队列 + 服务端逐操作确认 | 可离线读写和恢复同步，保留现有平台，需要补充业务仓储和同步协议 | 采用 |
| 在 Android 内嵌整套 Node 服务与服务器数据库 | 安装、运行和跨平台维护复杂，仍需解决同步冲突 | 不采用 |

逻辑边界：页面 → 本地业务仓储 → SQLite 与本地附件；同步协调器 → 网络传输层 → 服务端业务规则。网络响应写回本地后通知页面刷新。不得在 `ApiClient` 内堆积全部本地业务或伪造网络登录成功。

## 4. 身份与进入流程

1. 首次启动立即建立设备内本地空间，进入买家首页；本地商家空间可直接切换，用于商品和店铺内容准备。明显标注“本地模式”，设置中保留网络登录/注册入口。
2. 已有安装升级：迁移已有账号标识、角色及购物车，保留原“记住登录”的网络凭据偏好；本地进入资格与服务器 token 分离。未记住网络登录不等于删除本地内容。
3. 欢迎页不再强制等待三秒或等待 `auth/me` 返回。先进入所属本地空间，账号验证在后台进行。
4. 无网络/服务不可用只改变连接状态；401 表示需要重新验证网络账号，保留本地内容和未上传操作。禁止通过错误文案匹配来决定删除本地身份。
5. 网络登录后显式展示当前本地空间将关联的网络账号，用户确认绑定后再上传。不能用输入的用户名推定服务器身份，不能自动注册同名网络账号。
6. 空间绑定后固定属于该服务器账号与服务地址；切换账号进入独立空间。退出网络登录清除相应凭据和停止其同步，保留数据；网络角色由服务器验证，本地商家入口不赋予网络商家权限。
7. 本地昵称、头像可编辑；网络注册、密码修改和找回必须在线完成，不把密码放进同步队列。网络账号或商家被停用后仍可查看本地空间，受限网络操作标为需要处理。

## 5. 本地业务覆盖范围

所有本地保存均先完成事务，再向页面显示成功；成功文案说明本地保存或待同步。以下每类都是验收范围，不能只实施缓存而遗漏写入。

| 业务 | 离线行为 | 联网同步行为 |
| --- | --- | --- |
| 商品列表、分类、搜索、商品详情、评价列表 | 已同步数据本地查询，图片优先读本地；无数据时明确空态 | 使用现有可见性规则刷新，隐藏/下架内容不继续作为可购买商品 |
| 全新安装内容 | 提供最小内置分类与明确标注的本地示例商品，演示浏览与下单；可创建自己的商家商品 | 示例记录永不自动上传，不对应真实库存或商家；自行创建内容按网络权限同步 |
| 收藏、购物车、地址 | 本地增删改、选中与默认地址设置立即生效 | 按所属账号与实体同步，保留明确删除标记 |
| 社区帖子、评论、点赞、个人内容 | 创建本地帖子及评论，保存图片，点赞切换立即显示 | 先上传附件与父帖子，再上传评论；不可见或已删除目标返回可处理状态 |
| 用户资料、头像 | 昵称和头像本地更新；账号凭据设置明确需联网 | 网络账号验证后同步可修改资料，用户名占用等返回冲突 |
| 通知 | 查看已同步通知、标记已读、删除立即本地生效 | 同步所属用户通知状态，服务端新通知通过刷新进入本地 |
| 商家申请、店铺资料 | 本地填写和保存申请/店铺资料 | 提交申请并显示真实审核状态；本地模式不能自行审批 |
| 商家商品与图片 | 创建、编辑本地商品，保存上下架/送审意向 | 核验商家权限、分类和当前审核状态后执行；上传不等于审核通过 |
| 订单、支付、取消、收货、发货、物流、评价 | 对已有或本地订单保存操作意向并给出本地预览 | 校验实际状态、版本和归属后依序确认，不在本地改写服务器确认状态 |

无缓存的其他用户私有数据、未下载的音频/AR 资源无法在断网时获取，界面明确提示待联网。公开示例内容不包含真实账号、订单、用户图片或业务数据库。

订单采用双状态：`confirmedState` 为最后服务器确认状态，`pendingAction` 为待同步操作。本地下单保存商品、数量、地址和价格快照；重连若价格或可用库存改变，暂停并要求用户处理，不能按新金额静默付款。现有演示支付仅作为现有系统业务，离线保存的是付款意向；服务端实际确认后才能显示支付成功。真实支付接入不在范围内。

本地示例订单只在本地演示，不上传到真实服务器；自建商家商品同步并审核可见后，才可被网络订单引用。订单过期、已取消、非本人或状态不适合时保留未确认意向并展示原因。

## 6. 本地持久化结构

使用 Android `SQLiteOpenHelper` 管理数据库版本，避免本次为本地库更换语言或 UI 框架。业务查询与文件处理放在后台执行，页面回调回主线程。

- `local_spaces`：本地空间 ID、服务地址、绑定网络用户 ID、当前本地角色、网络验证状态。
- `local_entities`：空间、资源类型、本地 UUID、远端 ID、JSON 业务内容、服务端版本、本地修订号、确认快照、删除标记、是否示例。唯一键包含空间和资源类型；常用查询字段增加独立列和索引。
- `local_media`：空间、附件 UUID、私有文件路径、SHA-256、媒体用途、远端 URL、上传状态及引用关系。
- `sync_operations`：空间、操作 UUID、实体 ID、动作类型、不可变请求载荷、请求哈希、基线版本、依赖操作、状态、重试次数、下次执行时间、失败码。
- `sync_results`：操作 UUID、服务器返回 ID/版本与结果；在同一事务中保存结果、替换临时引用、确认本地快照与标记队列完成。

本地实体更新和队列写入必须同事务；写入失败不显示保存成功。金额用整数分。删除保留墓碑至服务器确认。成功同步的操作可压缩为结果记录，未确认操作与在用附件不能因缓存清理被删除。

既有购物车迁移采用可重复执行标记；升级失败保留原数据并阻止损坏写入，不能清库重建。文件存放应用私有目录，不依赖临时裁剪文件；附件先写临时文件，再原子替换并建立引用。数据库与附件从 Android 自动云备份中排除，避免跨设备恢复产生账号/队列错配。

## 7. 同步协议与调度

### 7.1 服务器协议

在 `/api/v1` 下增加经过现有鉴权的 `/sync/operations`。每次提交一个白名单业务操作，正文包括协议版本、客户端实例 ID、操作 UUID、动作、引用实体、基线版本、请求载荷和载荷哈希。身份与权限从 token 获取，客户端提供的角色或用户 ID 不能覆盖鉴权结果。

服务器增加操作回执表及必要的实体版本字段/映射，回执以“网络用户 ID + 操作 UUID”唯一。相同 UUID 与相同载荷返回既有结果；不同载荷返回冲突。业务写入与成功回执在同一数据库事务完成，消除服务器成功但客户端未收到响应造成的重复写入。回执不能仅存在进程内或按短期日志策略删除。

业务动作调用从现有路由提取的共享业务函数，保持网页与 APP 校验规则一致；不在服务器内部通过 HTTP 回调自身接口。事务提交后才广播刷新事件；失败不能留下部分业务写入或成功回执。现有接口保持兼容，实体版本必须在网页和 APP 所有相关写入口更新。

图片上传补充按账号和操作 UUID 的回执，校验体积、格式、归属与内容哈希，不能把任意本地路径作为服务器 URL。文件操作采用暂存、落盘和可恢复记录，确保响应丢失后能够取回同一次上传结果；仅业务实体写入使用 SQLite 原子事务，不声称数据库与文件系统天然原子。

### 7.2 执行顺序与恢复

1. 应用前台启动、手动重试、设备网络恢复触发健康检查；可用后验证绑定账号，再执行上传。使用系统网络回调需要补充相应网络状态权限。
2. 一个空间同时只有一个上传执行器；默认只在应用前台自动同步，退出后队列保留，下次进入自动恢复。不要承诺应用被强制停止后仍立即同步。
3. 按依赖关系执行：附件 → 地址/商品/帖子等实体 → 订单/评论 → 后续状态操作。临时 ID 通过持久化映射替换；父操作失败仅阻塞依赖项，其他独立实体继续。
4. 操作 UUID 和已发送载荷不得在重试中改变。对尚未发送的购物车数量、点赞等状态可合并；已发送但结果未知的操作必须先取得回执，再生成后续操作。
5. 网络错误、超时和 5xx 指数退避（约 2、5、15、30、60 秒，随后最长五分钟，带抖动）；401 等待网络登录，403/409 与确定性 4xx 进入需要处理状态。429 遵从服务端重试时间；不无限高频重发。
6. 上传确认后刷新受影响的本地资源。首次绑定使用可分页的资源快照下载，后续复用现有查询和事件触发刷新；第一版不引入全局变更日志或声称具备任意时长增量游标。
7. 列表快照完整下载成功后才更新快照范围内的删除/不可见状态；部分失败不能把“未返回”当作删除。拉取结果写入确认快照，再重放未确认本地操作，避免覆盖待上传编辑。
8. 切换账号/服务地址时取消旧任务并通过空间和执行代数检查丢弃过期回调，旧任务不得写入新账号空间。

## 8. 冲突规则与界面反馈

- 服务地址、空间和账号必须同时匹配。新空间合并到已有绑定空间时使用一次性迁移事务并保留映射，不按用户名匹配合并。
- 收藏、点赞、已读采用明确目标状态；购物车采用期望数量而不是重复累加。删除与修改冲突进入处理列表。
- 地址、昵称、商品、店铺资料使用服务端版本或确认快照检查并发；另一端已修改时展示本地与服务器内容，用户选择后产生新的操作 UUID 和新基线。
- 订单状态、价格、库存、审核状态以服务端校验为准；跨端冲突保留本地意向供处理，不能悄悄覆盖或删除。
- 首页/个人中心提供轻量状态入口：本地模式、服务未连接、同步中、已同步、需登录、需要处理；展示待同步数量、最近成功时间、失败原因及重试按钮。
- 用户可以查看待同步内容与冲突详情；丢弃操作前说明影响。尚未上传的私人附件不自动删除，清理需检查引用。
- 不重新探索整套视觉风格，沿用现有组件和颜色；对新增状态与入口提供实际运行预览。

## 9. 控制中心日志与启动优化

恢复主界面“运行日志”按钮，并保留设置菜单入口；日志窗口沿用现有日期、级别筛选、刷新与三天保留规则。按钮在服务关闭/启动/失败时也可用。检查默认尺寸、最小尺寸、字体缩放及系统缩放，避免按钮或日志首行裁切。

启动优化先建立同机基线，分别记录：控制中心打开到可响应、点击启动到 API 健康、点击启动到网站登录页可用。冷启动（依赖与构建缺失）和暖启动（输入未变且产物有效）分开，暖启动至少测三次并记录范围与中位数。

采用一次准备进程统筹依赖/构建检查与数据库准备，减少重复启动 Node/PowerShell 的成本；健康状态探测在启动阶段适当提高频率，运行稳定后回到低频。是否并行构建只在测量显示收益且不会争抢资源时决定。

保留构建输入与产物完整性校验，变化或损坏时自动重建；不能仅凭文件存在或 mtime 判断可复用。保留迁移检查，初始化逻辑验证幂等且不覆盖业务修改。数据库迁移/构建失败不得报服务已就绪，打开网页必须等 API 与网站产物就绪。

指标：同机暖启动中位数争取下降至少 20%；如现有缓存已使该指标无法合理改善，则如实报告分段耗时与实际收益，不减少正确性检查来达标。APP 正常已有本地空间时不等待网络进入主页，专项验证服务关闭情况下的可操作时间。

## 10. 验证、交付与范围约束

实施顺序：先日志入口与启动测量；再本地身份/仓储和浏览读写；然后各业务离线能力、服务器协议与同步；最后冲突和跨端联调。最终交付必须覆盖第五节各业务，阶段结果不能标为全部完成。

必须验证：

1. 全新安装并关闭服务：可进入买家/商家本地空间，示例内容有标记，创建地址、帖子、商品、本地订单意向后重启仍保留。
2. 升级安装：既有登录偏好、购物车与未修改资源保留，不要求卸载清数据。
3. 已关联账号断网编辑，服务恢复后正确同步，网页可见对应结果；应用重启后队列继续。
4. 服务器已提交后模拟响应丢失，重试不重复生成订单、帖子、评论、商品或附件；同 UUID 换载荷被拒绝。
5. 图片和父实体依赖、部分失败、进程中断、本地写入失败恢复；失败不能显示网络成功或丢失操作。
6. 双端改动、库存不足/价格变化、订单过期、角色取消、账号停用、通知删除及换账号时不存在覆盖、越权或串号。
7. 本地示例数据永不上传，首次真实数据同步与空态正确；外部未缓存资源有明确提示。
8. 控制中心日志可见可用、字号/尺寸布局、服务启动/关闭/端口占用、构建复用/输入变化/产物损坏、分段启动耗时。

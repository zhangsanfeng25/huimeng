# 绘梦 V1.2 AI 助手与身份系统实施计划

> 在当前会话使用 executing-plans 分阶段实施。每阶段通过对应验证后再进入下一阶段。

**目标**　增加三种角色的 AI 助手，并把用户和商家的权限绑定到本次登录所选身份。

**架构**　沿用 Android Java/XML、React 管理后台和 Node.js/Express/SQLite 服务。服务端验证身份、配置和数据范围。AI 客户端只访问绘梦后端。现阶段通过测试替身演练，实际服务商由用户后续对接。

**依据**　用户提供的《绘梦 App V1.2 AI 助手与身份系统改造实施方案》及本地基线、服务商和模拟器环境的补充决定。

## 交付边界

- 以 `HuGo/local-first-sync` 当前工作区为基线，包含已有未提交改动。先记录基线和改动范围，不回退、不覆盖既有工作。
- 沿用原有页面、导航、配色、间距和组件。Android 新增浮层，网页在原管理后台侧栏增加「AI 管理」。
- 首次验收连接模拟器的 `10.0.2.2:3000`，以本地可运行源码和模拟器联调结果为交付。实际模型调用验收留到服务商接入后。
- GitHub 上传留待用户提出。届时按 `docs/version-management.md` 更新源码和带版本号的 APK，保留历史 APK 和标签。核对待提交文件、发布说明、APK 和构建输入，排除 API Key、加密主密钥、签名材料、本地配置、业务数据库及用户上传文件。

## 1. 登录、鉴权与待同步数据

涉及 `server/src/core/http.ts`、`server/src/modules/auth.ts`、`server/src/modules/customer-services.ts`、`server/src/sync/`，以及 Android 登录、个人页、会话存储和同步模块。

- [ ] 建立基线，核对版本、依赖、既有测试及 Android 构建环境。验证使用临时数据库和测试账号。
- [ ] 增加接口回归用例。用同时拥有用户和商家资格的账号分别登录，断言用户会话访问商家 API、上传商家图片、推送商家操作或读取商家快照时被拒绝。用商家会话访问用户专属接口时同样被拒绝。构造旧切换请求、`X-Service-Role` 和跨身份续读快照，确认无法切换权限。记录改造前的失败用例。
- [ ] 保留登录页已有身份选择，删除登录后的 `RoleSwitchActivity` 入口及注册。服务端删除角色切换的写入行为。鉴权使用会话 `active_role`，检查该身份是否仍有效。账号角色列表继续供登录提示和申请状态使用。商家获批后需要以商家身份重新登录，停用或撤销后旧商家会话失效。
- [ ] 在同步入口和幂等回执查询前执行身份校验，防止旧回执或分页快照泄露其他身份的数据。现有商家申请入口、通知、社区、收货和售后按各自角色回归。
- [ ] 退出时暂停产生新同步任务，有网络时做一次有时限的同步，然后结束会话。为队列绑定提交身份，待同步操作保留在原账号下，由匹配身份恢复。升级时保留现有数据库和操作 ID。旧队列中可由业务动作确定身份的记录按动作归属，无从确定的记录保留并提示处理。离线商家登录使用已在线验证过的商家身份，在线恢复后重新验证权限。
- [ ] 验证断网退出、重新打开 App、换身份登录、回到原身份补传、商家获批和撤销。执行服务端测试、类型检查和 Android 构建。

## 2. 后台 AI 管理

涉及 `html/src/App.tsx`、`html/src/components/AppShell.tsx`、新增 `html/src/pages/AiManagementPage.tsx`，以及服务端独立配置与统计模块。

- [ ] 用临时数据库验证管理员权限、读回配置、留空保留旧 Key、更换 Key、加密失败、以及日志和响应脱敏。验证现有库和归一化库都可增量创建 AI 专用表。
- [ ] 实现 `GET`、`PUT /api/v1/admin/ai/config`，以及 `POST /api/v1/admin/ai/connection-test`。配置单个接口地址和模型，返回 `keyConfigured`、启用状态和测试结果等安全字段。Key 用服务端环境提供的主密钥加密，环境示例只提供变量名和说明。主密钥缺失时拒绝保存真实 Key。
- [ ] 新页面沿用后台原有表单和状态反馈，展示接口地址、模型名、Key 输入、连接测试、启用开关及按角色汇总的基础统计。服务商未接入时明确显示状态。本地测试替身的测试结果标注为模拟。

## 3. 服务端 AI 请求和测试替身

- [ ] 定义 `POST /api/v1/ai/chat`。请求仅传功能、当前消息和有长度上限的本次对话上下文。角色以服务端登录会话为准。响应包含答复文本及可选的推荐商品。测试匿名访问、越权功能、禁用、超时和无效响应。
- [ ] 定义独立模型适配接口，由显式开启的本地联调配置注入模拟响应。生产路径默认关闭，当前阶段不接入真实服务商、不产生第三方调用。模型适配器只接收对应功能需要的数据。
- [ ] 为每次调用设置超时，限制输入和上下文长度，按角色记录成功、失败和耗时等汇总。调用统计不存聊天内容、Key 或原始上游错误。不设置每日次数配额，不走 Android 离线队列。

## 4. Android 悬浮球和对话浮层

涉及 `MainActivity.java`、`activity_main.xml` 和新增的 AI 浮层组件，复用现有颜色、按钮、圆角和留白。

- [ ] 在用户和商家主界面增加悬浮球，支持拖动、贴边和位置恢复。用窗口内可用区域约束位置，验证旋转、键盘弹出和底部导航下的布局。
- [ ] 使用默认半屏的聊天浮层，支持展开、返回和收起。对话状态只在当前登录期间的 App 进程内保留，退出或进程重启后清除。游客沿用现有登录流程，断网时提示在线使用。
- [ ] 验证用户和商家菜单、键盘、关闭重开、退出换身份以及商城原有主页面和导航。

## 5. 社区热度与真实商品推荐

- [ ] 从公开社区帖子及其关联商品、公开评论和点赞计算近期热度。首版按近 30 天统计并短时缓存。用固定测试数据验证已下架、缺货、年龄不符、隐藏帖子、缺失年龄和无候选项。含明确年龄需求时，无法可靠匹配年龄的商品不进入该次候选。
- [ ] 先筛选可售和符合明确要求的绘本，再按社区热度排序。服务端最多返回三件商品及其真实 ID、封面、名称和价格。模型解释由候选数据约束，理由缺失时用已知商品信息生成提示。
- [ ] 缺少关键需求时优先问一至两个问题，需求明确时直接推荐。Android 点击商品卡片后收起聊天并打开现有商品详情，返回后可继续当前对话。

## 6. 三种角色的 AI 功能

- [ ] 用户菜单提供绘本推荐、社区热门、阅读咨询和自由对话。仅使用可公开展示的商品及社区信息。
- [ ] 商家菜单提供热门选品、商品文案、社区需求分析和店铺经营建议。验证店铺数据只来自当前商家，社区信息限公开内容。
- [ ] 管理员在「AI 管理」使用平台趋势、商品热度、运营建议和数据分析。查询使用限定的汇总指标。当前版本的 AI 功能只读，不暴露商品、订单或退款写入工具。

## 7. 验收和交付

- [ ] 使用同一版本的后端、后台和 APK 核对身份隔离、离线队列、密钥处理、AI 禁用与模拟联调、推荐真实性、主要商城流程和现有界面。运行 `npm run lint`、`npm run build`、`npm test` 和 Android 构建。记录具体测试及未验证项。
- [ ] 记录模拟器启动方式、模拟 AI 启用方式、管理员配置入口、服务商适配位置和真实服务所需的部署条件。
- [ ] 在用户要求上传时再核对远端最新版本和发布范围，递增 Android 版本，构建并核对 APK 内部版本、签名和 SHA-256。按项目规则发布源码和独立 Release 附件。

# 1.1.5 付款与订单进度验证

本次在既有三端服务功能上修复付款恢复与订单进度；未发布到 GitHub。日志及截图位于 `output/order-progress-1.1.5/`。

## 行为

- 订单详情的“物流动态”调整为“订单进度”，同时显示当前已确认状态与实际发生的操作。合并订单事件和售后事件，按时间倒序排列；不推测发货、运输、收货步骤。
- 待付款仅展示下单；付款完成后显示付款和准备出库；审核、退货、退款仅在对应记录存在时出现。仅本地保存的订单显示待联网确认。
- 付款前校验服务端登录和订单归属；缺少登录时进入原账号登录，成功后回到同一笔付款。其他买家不能接续该订单。
- 已排队的付款继续确认原请求；重复点击不会新增付款。只有服务端确认 PAID 才显示成功。断网、登录失效和等待超时提供明确状态与重试入口。
- 请求绑定页面代次与登录令牌，旧请求不能清除新会话；离开、返回和重新确认会清理旧轮询及忙碌状态。

## 边界

仍为 DEMO 支付和退款，不产生真实扣款。原账号旧本地订单需要本人登录该订单所属账号后同步，未绕过认证上传。模拟器 API 使用 `10.0.2.2:3000`，管理网页使用同一服务的 `127.0.0.1:3000`；测试则对应 3100。实体手机和 API 26 未实测。

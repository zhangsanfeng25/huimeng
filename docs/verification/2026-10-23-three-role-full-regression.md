## 发现的实际问题

1. **现有业务数据的 20 张商品封面文件缺失。** 数据库仍引用 `/public/books/p0001.png` 至 `p0020.png`，对应服务端文件不存在，实际服务 HEAD 请求均返回 404，网页显示缺图提示。只读检查共核对 50 条媒体引用，其中缺失 20 条，均为商品封面；社区及头像引用未发现同类缺失。新上传 JPEG 再下载可通过，说明需要处理历史商品图片资源，而非整体上传连通性故障。数据库 `integrity_check` 为 `ok`，外键检查无异常。
2. **后台反馈与售后模块共用搜索状态。** 在留言反馈输入 `QA三端联调反馈` 后切换售后管理，搜索词仍保留，列表误显示为空；清空搜索后 5 条售后数据恢复。`ServicePage.tsx` 的查询 state 未随 kind 切换重置。这是界面筛选问题，并非数据丢失。
3. **整单全额退款完成后仍显示再次申请按钮。** 手机详情已显示仅有 1 件商品、取消/退回 1 件、退款 29.80 元完成；订单接口也确认 `fulfillableQuantity=0`，但底部仍显示“对剩余商品再次申请”。`ServiceActivity.java:114` 仅按结束状态展示按钮，未检查剩余可售后额度。本次确认了多余入口，没有把该现象描述成重复退款成功。

上述业务问题本轮仅检查记录，未修改业务代码。

## 测试中的调整和验证限制

- 对 2 个既有 Android 测试文件调整了过时预期：登录帮助改为当前忘记密码入口、售后表单选择商品、取消旧关联弹窗等待、个人页消息检查忽略隐藏消息 Fragment。最终重跑相关测试通过。初次失败和中断日志也保留，未将其算作通过。
- 网页“确认演示退款”触发确认弹窗后，浏览器自动化连接超时，无法可靠读取弹窗；关闭该临时标签页后，用同一测试管理员接口完成确认，再在新网页和手机核对完成状态。因此**网页最终确认按钮的完整点击链路未验收通过**，不能由接口成功替代这项结论。
- 支付和退款均为 DEMO，不涉及支付宝、微信或银行卡真实资金；邮箱/电话找回密码按已批准的本地演示逻辑测试，未验证短信/邮件验证码。
- Android 使用 API 34 模拟器，未覆盖实体手机、其他 Android 版本、外部网络或多台实体设备并发。模拟器时间显示时区与 Windows 不同，截图中的时刻需按各自时区理解。
- 105 项批量界面测试含模拟网络；另外 7 项及 16 组 HTTP 场景使用真实服务，二者分别计数，不把模拟界面通过等同于实际通信成功。
- 本次无生产业务修复。正常 Android 包与默认 `http://10.0.2.2:3000/api/v1/` 已恢复构建；隔离服务、模拟器在测试后关闭，历史 APK 保留。

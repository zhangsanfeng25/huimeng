# 聊天、售后与反馈数据查看

本项目使用本机 SQLite，网页和 Android 通过同一个 Express 服务读写业务库。Android 另外保存离线缓存和待同步队列，并不是直接连接服务端数据库。

默认业务库为 `D:\bishe\huimeng\server\data\huimeng.db`，以 `server/.env` 的 `DATABASE_PATH` 配置为准。控制中心启动共享服务后，网页访问 `http://127.0.0.1:3000`，本机 Android 模拟器访问 `http://10.0.2.2:3000/api/v1/`。实体手机必须使用可到达电脑的局域网地址重新配置，不能使用模拟器专用地址。

可用 DB Browser for SQLite 或其他支持 SQLite 的数据库工具，以只读方式打开业务库。服务运行时可能同时存在 `huimeng.db-wal` 和 `huimeng.db-shm`：不要删除它们，也不要只复制主文件当作完整在线备份。使用控制中心现有备份功能获得一致性副本后再离线查看更稳妥。

也可以使用控制中心现有“导出数据”功能：导出目录包含 `chat_messages.csv` 等分表文件以及汇总 `data.json`，可以直接搜索消息正文、会话编号和订单编号。新增 8 张表均包含在内。导出文件保存在你选择的本地目录，应和业务库一样妥善保存。

## 数据表

| 表 | 内容 |
| --- | --- |
| conversations | 买家与店铺的固定会话 |
| chat_messages | 消息正文、发送人及角色、时间、关联商品或订单 |
| conversation_reads | 买家和商家的已读位置 |
| after_sales | 售后类型、金额、原因、状态与退货物流 |
| after_sale_events | 各阶段处理记录 |
| refunds | 演示退款流水，按订单及售后单防止重复退款 |
| feedbacks | 用户或商家提交的反馈 |
| feedback_replies | 平台回复和提交人的后续补充 |

迁移文件为 `server/migrations/010_customer_services.sql`，按现有迁移机制增量执行，不清空旧数据。聊天和业务内容保存在本机服务端，数据库、备份、上传图片及本地配置不上传源码仓库。

## 只读查询示例

打开 `docs/sql/customer-services-readonly.sql`，按会话、订单或反馈编号替换示例条件。消息时间以库内时间为准，客户端显示会转换为本地时间。下列查询不包含密码或登录令牌。

登录后发送的聊天、提交的售后与反馈以服务端写入成功为准。离线缓存可以阅读，未成功提交时会保留草稿并提示错误。购买采用原有离线队列；未登录原账号时只保存在本地，需要登录相同账号后同步，不能将本地保存提示当作平台已收到订单。

当前退款是 DEMO 演示退款，支持单个店铺订单的整单全额处理。商家初审后交平台复核，退货退款还需买家填写物流及商家确认收货，再由平台登记退款；不涉及真实支付渠道转账。
